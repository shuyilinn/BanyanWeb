Reasoning by tree search

rStar-Math (arXiv:2501.04519) solves a math problem by Monte Carlo tree search: the model writes a reasoning step with Python code, the code is executed, and the search decides which partial solution to extend next.

On Banyan the search policy is a Python method and the code execution is an environment call. Both sides search the same sixteen GSM8K questions together, with the same model, settings and seed; the trees below are one question's.

Why the time varies from run to run

A run ends when its last question ends. On Banyan each question is searched on its own, so fifteen of the sixteen were done by s in the run above, and question 13 went on alone until s. The authors' code advances all sixteen questions one search step at a time, so every step waits for the slowest question's samples.

Question 13 is slow because the model sometimes stops writing steps and starts thinking aloud ("Okay, let's see. Carlos wants to know…", weighing 12 against 13 years) until a step reaches its 2,048-token limit. An expansion waits for its longest sample, so one such sample turns a half-second expansion into one of 18 to 36 seconds; and once a long step is in the tree the search often returns to that branch (in two of the three runs most of the long expansions were in one branch). How often this happens depends on the draws: question 13 took 114 s, 221 s and 367 s in three runs of Banyan. The authors' trees show the same long steps on this question.

Setup

How this was measured

the authors' code
rStar's own search, through our evaluation's runner (its warm-up, seed and evaluator), with wrappers that note when each sample finished, when each step became a tree node and when each rollout ended. Their algorithm is not changed.
Banyan
The algorithm is our application on the user API. The measurement notes the time each tree node was made and wraps the application's own @pick, @grow and @judge to note when each step was returned and each answer judged; the measurement changes nothing in the system.
the runs
Three seeds per side, the two sides one after the other on the same card, never at the same time; the replay is the run that is each side's median (seed 2029 on both sides).
Banyan is a research system under development.
