Many samples per prompt

Synthetic training data, preference pairs and evaluation sets start as many samples from the same prompt. Here both sides draw 10,000 samples from Qwen3-8B for one GSM8K question, with the same decoding settings, on one H100 each.

Prompt

Both runs, on one clock

Press Play to replay the two measured runs in step. Left, vLLM computes the samples as rows: each sample is its own row and every row writes every one of its tokens. Right, Banyan computes them as a tree: samples that start with the same tokens share those nodes, and a node is written once however many samples pass through it. Below, the samples each side has finished so far.

Each side is drawn left to right: the prompt is on the left edge and the horizontal position is the token position in the sample (the dashed line is the 128-token limit). Left: vLLM's 10,000 samples, one horizontal line each, top to bottom in the order vLLM started them (it writes 1,024 at a time); a line is dark blue while vLLM is writing it and light once it is written. Right: Banyan's tree, top to bottom in text order so samples that begin the same way are next to each other; a line's width is the number of samples through it, and where samples split the line branches downwards. How this was measured

vLLM
generate() is called unchanged. Two wrappers in vLLM's output processor note, at every engine step, the time and which rows got a token, and when each sample finished. A row gets at most one token per step.
vLLM's batch size
The page shows vLLM at the evaluation baseline's setting, 1,024 rows at once (max_num_seqs). Its KV cache was then about half used, so it was also run with more rows at once; the total time hardly changes:
Banyan
The algorithm is the evaluation's application on the user API. The measurement notes the time each node of the tree was made (the runtime's own new-node callback, no change to the system), and, with a @judge on the user API, when samples finished.
the cost of noting
Each side ran the timed part twice, with and without the notes: vLLM ; Banyan . The replay uses the runs with notes.
