Many samples per prompt

Synthetic training data, preference pairs and evaluation sets start as many samples from the same prompt. Here both sides draw 10,000 samples from Qwen3-8B for one GSM8K question, with the same decoding settings, on one H100 each.

Both runs, on one clock

Press Play to replay the two measured runs in step. Left, vLLM computes the samples as rows: each sample is its own row and every row writes every one of its tokens. Right, Banyan computes them as a tree: samples that start with the same tokens share those nodes, and a node is written once however many samples pass through it. How this was measured

vLLM
generate() is called unchanged. Two wrappers in vLLM's output processor note, at every engine step, the time and which rows got a token, and when each sample finished. A row gets at most one token per step; the left circle is drawn from these records, including the steps in which vLLM paused a row.
vLLM's batch
The page shows vLLM at the evaluation baseline's setting, 1,024 rows at once (max_num_seqs). At that setting its KV cache was about half used, so it was also run with more rows at once; the total time hardly changes:
Banyan
The algorithm is the evaluation's sampling application with n = 10,000. The measurement notes the time each node of the tree was made (the runtime's own new-node callback) and, with a @judge on the user API, when samples finished; the right circle is drawn from these.
