Five applications written on Banyan, in two kinds of workload. Each page describes the method and replays a baseline run (left) and a Banyan run (right) side by side.

Sampling workloads

The workload draws many independent samples from the same prompt: to estimate a rate, build a dataset or audit a model. vLLM computes each sample as its own row; Banyan computes them as one tree, so tokens that samples share are computed once.

  • Many samples per prompt

    10,000 samples of one GSM8K question with Qwen3-8B: vLLM's 10,000 rows against Banyan's one tree.

    85.4 s → 20.8 s
  • Did the model forget? Leak rate after unlearning

    1,024 judged answers per question for a model trained to forget, against vLLM's batched sampling and the same judge.

    7.0 s → 4.8 s
  • How often does a model give a harmful answer?

    Estimate a rare harmful-answer rate by sampling from a refusal-ablated copy of the model and reweighting to the original.

    2 → 13 harmful found

Search workloads

The workload is a search: an algorithm decides which partial output to extend next, often with a judge or an environment in the loop. The reference implementations send each step to the engine as new requests; Banyan runs the search inside one tree on the GPU and keeps the batch full.

  • Reasoning by tree search

    rStar-Math's Monte Carlo tree search with code execution, against the authors' implementation.

    532 s → 115 s
  • Jailbreak search

    BOA's search for a jailbreak among a model's likely responses, 600 seconds, against the authors' implementation.

    22,193 → 1,021,692 nodes
