Banyan
OverviewUse cases

Banyan is a system for LLM workloads that need many outputs from one model instead of one answer: measuring how often a model gives a harmful answer, generating a dataset, auditing what a model still knows, searching for a correct solution. An algorithm is written as a short Python class that says how to steer the model, how to draw each token, when to call a judge and which branches to expand or prune. Banyan runs it on the GPU next to the model and keeps everything it generated as one tree of tokens, in which samples that begin the same way share the same nodes.

What Banyan provides

  • Algorithms as Python classes. A sampler or a search is one class with a few decorated methods (@steer, @sampling, @judge, @prune, a search policy). The per-token parts are compiled to run on the GPU with the model; the rest is ordinary Python.
  • One tree per prompt. A node keeps the candidate tokens at its position with their log-probabilities, so more samples can be drawn at a branch point without another forward pass.
  • Steering, with the original model alongside. A direction can be added to or removed from the hidden state at chosen layers and token positions, and the unmodified model's probability of every generated token is kept next to the steered one.
  • Judges inside the loop. Classifier and LLM judges score samples as they finish; search policies read the scores to decide what to expand.
  • Every run is saved. A run writes its trees to disk. The replays on the use-case pages are drawn from those files.

Banyan uses vLLM as its model library and adds its own attention kernel, sampler and scheduler.
